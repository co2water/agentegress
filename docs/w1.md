## 新發現（修正了 Spike 0 的假設）

1. **DNS 快取幾乎沒用。** 本機快取裡只有十來個名稱，原因有三：TTL 很短；Chrome 等程式自己解析 DNS，不經過系統快取；Agent 的長連線早在記錄過期前就建立了。→ 改用內嵌的官方 IP 範圍標註公司。Agent 連線現在都能顯示 `[Anthropic]`。
   - Anthropic 的範圍經 RDAP 驗證：`160.79.104.0/21` 和 `2607:6bc0::/32`。
   - 其他來源：Cloudflare、Google、Google Cloud、AWS、GitHub（排除 actions 範圍，因為那是 Azure 的 IP）、Fastly、Microsoft 365。
2. **Claude Desktop 的 MSIX 虛擬化。** 從 Claude 內部啟動的行程看到的 `%APPDATA%` 會被導向別處；從外部看，設定檔實際位於 `Packages\Claude_*\LocalCache\Roaming\Claude\`。兩個路徑都要讀。
3. **Windows 中文環境的編碼問題。** 下游工具如果用系統代碼頁（CP950/936）讀取 JSON，路徑中的中文字元可能產生無效的跳脫序列。agentegress 的輸出一律是 UTF-8，README 需要提醒使用者：在 Python 裡要用 `sys.stdin.buffer` 讀取。

## 已知限制（留給 W2 和之後處理）

- **Azure 的 IP 沒有標籤。** Azure 的 service tags 下載網址每週都會變，本機觀察到的 Azure 位址因此沒有標籤。另外，騰訊、字節跳動、LINE 等亞洲業者沒有公開的 IP 範圍清單。
- **敏感資料遮蔽只能靠格式比對。** 已知格式的 token 都能遮蔽，例如 `ghp_`、`github_pat_`、`sk-`、`--token`、`key=`、URL 中的帳號密碼；但任意字串形式的秘密無法辨識。這點要寫進 README。
- **TCP only**：QUIC/UDP 看不到（P2 用 ETW）。
- **需要管理員權限的部分**：在一般權限下，系統服務的簽章和路徑讀不到，會標示為「— no access (needs admin)」。
